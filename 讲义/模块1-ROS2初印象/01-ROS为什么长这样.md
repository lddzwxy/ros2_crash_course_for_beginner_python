# 1.1 ROS 为什么长这样

> 模块 1 第 1 集
> 前置：已完成模块 0（Ubuntu 24.04 + 终端 + Python 3.12）。

---

## 一、本集目标

理解 ROS2 **解决什么问题**：进程间通信 + 工具链 + 生态。

本集不敲命令，把"节点 / 话题 / 服务 / 动作 / 参数"五件套的直觉建立起来。

---

## 二、效果演示

一张图（或白板动画）：两个**互不相识**的节点通过 Topic 说话。

```text
   [摄像头节点]  --图像数据-->  [识别节点]  --目标位置-->  [小车控制节点]
        ↑                       ↑
     不认识对方          只约定"话题名"和"消息类型"
```

**最终现象**：三个程序可以由不同的人、不同的语言写出来，只要**话题名和消息类型对上**，就能互通。

这就是 ROS2 的核心魔法。不写代码，先看懂这张图。

## 三、理论讲解

### 3.1 机器人软件为什么要解耦？

想象一台送货机器人，里面至少有：

- 摄像头驱动（C++，厂商提供）
- 雷达驱动（C++）
- 建图算法（Python）
- 导航算法（C++）
- 语音播报（Python）

如果把它们写成**一个大程序**：

| 问题 | 后果 |
| ---- | ---- |
| 一家公司写不完 | 算法、驱动、UI 要多团队 |
| 一处崩溃全完蛋 | 雷达驱动挂了，导航也死 |
| 换个雷达要改整个工程 | 无法复用 |
| 调试像拆炸弹 | 不知道是哪段出错 |

**解耦**：拆成多个小程序，互相**只通过消息**说话。谁坏了换谁，谁写的都行。

### 3.2 ROS2 = 通信中间件 + 工具 + 生态

| 它是什么 | 内容 | 比喻 |
| -------- | ---- | ---- |
| **通信中间件** | Topic / Service / Action / 参数 | 公司的电话、邮件、快递系统 |
| **工具链** | `ros2` 命令行、录包、日志、可视化 | 螺丝刀、万用表、监控室 |
| **生态** | 驱动、导航、仿真插件、算法库 | 现成零件市场 |

它**不是**：

- 一个装完就有窗口界面的软件；
- 一个实时操作系统；
- 一门新的编程语言（你仍然写 Python / C++）。

### 3.3 五件套直觉（生活化比喻）

| 概念 | 生活比喻 | 适合干什么 |
| ---- | -------- | ---------- |
| **Node（节点）** | 一个工人 | 干一件具体活 |
| **Topic（话题）** | **广播电台** | 持续播报，谁想听谁听（速度、图像） |
| **Service（服务）** | **打电话订位** | 一问一答，要个结果（查询电量） |
| **Action（动作）** | **点外卖** | 长时任务 + 进度 + 可取消（走到目标点） |
| **Parameter（参数）** | 遥控器旋钮 | 运行时可调配置（速度上限） |

记忆口诀：

> **Topic = 广播，Service = 打电话，Action = 点外卖。**

怎么选？

| 场景 | 用什么 | 为什么 |
| ---- | ------ | ------ |
| 每秒发 30 次速度指令 | Topic | 高频、丢几条无所谓 |
| 查询"电量多少" | Service | 一问一答，要准确结果 |
| "去 3 号货架"，要进度、能取消 | Action | 长时、有反馈 |

### 3.4 包与工作空间

| 概念 | 是什么 | 比喻 |
| ---- | ------ | ---- |
| **Package（包）** | 最小交付单元：代码 + 依赖声明 | 一盒零件 + 说明书 |
| **Workspace（工作空间）** | 所有包的家 | 你的工具车间 |

后面你会亲手建 `~/ros2_ws`，在 `src/` 下放包。

### 3.5 另外两个词

| 概念 | 含义 |
| ---- | ---- |
| **消息类型（msg）** | 话题里传的数据格式，如 `Twist`（速度）、`Image`（图像） |
| **图（Graph）** | 当前所有节点/话题的连接关系总览 |

**类型对不上 = 听不懂**。就像广播用中文播，你只会英文，再努力也听不懂。

## 五、关键概念详解

| 概念 | 一句话定义 | 备注 |
| ---- | ---------- | ---- |
| **Node** | 一个执行具体任务的进程 | 一个机器人"工人" |
| **Topic** | 异步广播通道，一对多 | 订阅者可随时加入 |
| **Service** | 同步请求/响应，一对一 | 会等结果 |
| **Action** | 目标 → 反馈 → 结果，可取消 | 适合长时任务 |
| **Parameter** | 节点的可配置项 | 可命令行/YAML 覆盖 |
| **msg** | 消息的数据结构 | 类型不匹配则不通 |
| **Package** | 代码 + 元数据 + 依赖 | 交付/复用的最小单位 |
| **Workspace** | 组织多个包的目录 | 后面用 `~/ros2_ws` |
| **Graph** | 运行时的节点/话题连接图 | 用 CLI 可以查看 |

## 六、常见坑

| 报错 / 现象 | 原因 | 解法 |
| ----------- | ---- | ---- |
| "装完 ROS2 就该有界面" | 概念误解 | 它是开发框架；界面工具要单独启动 |
| "ROS2 是实时操作系统" | 概念混淆 | ROS2 是通信框架；硬实时另说 |
| "Service 传高频传感器数据" | 用错通信方式 | 高频数据用 Topic |
| "Action 只是更快的 Service" | 理解不到位 | Action 有反馈、可取消、适合长时 |
| "一个包必须只放一个节点" | 误解包的定义 | 一个包可以含多个可执行 |
| 一上来学导航/机械臂 | 顺序错了 | 先 M1–M4 打好通信与工程底子 |
