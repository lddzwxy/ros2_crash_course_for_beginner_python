## 三、理论讲解

### 3.1 决策树

```text
要传的数据是什么？
│
├─ 连续的数据流 / 指令 / 状态
│   └─▶ Topic
│
├─ 一次请求，要一个明确结果
│   ├─ 瞬时完成（开灯、查电量）→ Service
│   └─ 耗时长、要进度、可能取消 → Action
│
└─ 可读可写的配置项
    └─▶ Parameter（模块 4）
```

### 3.2 一张表背下来

| 信号特征 | 选 | 例子 |
| -------- | -- | ---- |
| 高频、单向、丢一条无所谓 | Topic | `/scan`、`/odom` |
| 高频、单向、尽量不丢 | Topic（Reliable） | `/cmd_vel` |
| 低频、要回执 | Service | `/set_mode`、`/spawn` |
| 长时、要进度、可取消 | Action | `/move_distance`、导航 |
| 配置、可在线改 | Parameter | `speed_mps`、`publish_frequency` |

### 3.3 全局话题 vs 私有服务

| 名字风格 | 适用 | 例子 |
| -------- | ---- | ---- |
| 全局 `/cmd_vel` | 跨节点公共数据 | 速度指令、状态 |
| 私有 `~/set_mode` | 只给自己的组件用 | 节点内部配置 |

入门阶段：公共数据用**全局名**；只有本组件用的服务可以加命名空间（如 `/robot1/set_mode`）。

### 3.4 对照 CONTRACT

本系列契约（`code/CONTRACT.md`）已定：

| 话题 | 类型 | 通信 |
| ---- | ---- | ---- |
| `/cmd_vel` | `geometry_msgs/msg/Twist` | Topic |
| `/odom` | `nav_msgs/msg/Odometry` | Topic |
| `/scan` | `sensor_msgs/msg/LaserScan` | Topic |
| `/battery_state` | `sensor_msgs/msg/BatteryState` | Topic |
| `/goal_pose` | `geometry_msgs/msg/PoseStamped` | Topic |
| `/delivery_state` | `std_msgs/msg/String` | Topic |

项目里自定义的：

| 接口 | 类型 | 通信 |
| ---- | ---- | ---- |
| `/set_mode` | `my_interfaces/srv/SetMode` | Service |
| `/move_distance` | `my_interfaces/action/MoveDistance` | Action |

## 五、关键 API / 命令详解

本集是设计集，没有新 API。记住选型口诀：

| 你要的是…… | 选 |
| ---------- | -- |
| 持续的数据流 | Topic |
| 一次请求一个结果 | Service |
| 长时任务 + 进度 + 取消 | Action |
| 配置项 | Parameter |

对应对象：

| 通信 | 描述文件 | 服务端 | 客户端 |
| ---- | -------- | ------ | ------ |
| Topic | `.msg` | `Publisher` | `Subscription` |
| Service | `.srv` | `Service` | `Client` |
| Action | `.action` | `ActionServer` | `ActionClient` |

## 六、常见坑

| 报错 / 现象 | 原因 | 解法 |
| ----------- | ---- | ---- |
| 全局滥用话题做请求响应 | 要"回执"却用 Topic，调用方不知成败 | 要确认结果的用 Service |
| 私有服务却起了全局名 | 多机器人/多实例冲突 | 加命名空间 `/robot1/set_mode` |
| 用 Service 传传感器 | 阻塞扛不住高频 | 换 Topic |
| 短任务做成 Action | 多写回调没收益 | 瞬时完成用 Service |
| 同一数据既 Topic 又 Action 发 | 语义重复、状态不一致 | 明确主通道，另一个只做辅助 |
