## 三、理论讲解

### 3.1 依赖要写在 package.xml，不要靠记忆

"反正我机器上有"是换机就挂的经典原因。ROS 的依赖声明分两层：

| 文件 | 写什么 | 不写会怎样 |
| ---- | ------ | ---------- |
| `package.xml` | `<depend>rclpy</depend>` 等 | rosdep / 别人不知道要装啥 |
| `setup.py` | Python 打包元数据 | 编译/安装缺文件 |

原则：**节点 import 了什么，package.xml 就要有什么**。

### 3.2 rosdep 是什么？

比喻：`apt` 是 Ubuntu 的应用商店，**rosdep** 是 ROS 包的"代购"——读你 `package.xml` 里的依赖名，翻译成 `apt` 包名（如 `std_msgs` → `ros-jazzy-std-msgs`），帮你装齐。

```bash
rosdep install --from-paths src -y --ignore-src
```

- `--from-paths src`：扫 src 下所有包；
- `-y`：不询问直接装；
- `--ignore-src`：工作空间里已有的源码包不算"缺依赖"。

### 3.3 README 三件套

| 段落 | 作用 |
| ---- | ---- |
| 版本卡 | OS / ROS / Python 版本，避免"我这边能跑" |
| 启动方式 | 复制即可跑的命令 |
| 节点表 | 谁干什么、话题是什么 |

### 3.4 lint（可选）

`ament_flake8` 查 PEP8 风格，`ament_pep257` 查 docstring。入门课不强制，但知道有这个工具：

```bash
cd ~/ros2_ws
colcon test --packages-select my_bringup
```

风格要点（写作规范）：4 空格缩进、类/函数有 docstring、文件头 3 行中文注释、变量函数名英文 PEP8。

### 3.5 目录长什么样才算干净

```text
my_bringup/
├── package.xml          ← 依赖清单
├── setup.py             ← 打包 + data_files + entry_points
├── setup.cfg            ← 脚本安装路径
├── README.md            ← 版本卡 + 启动 + 节点表
├── resource/my_bringup  ← ament 索引占位
├── my_bringup/          ← Python 源码
│   ├── __init__.py
│   ├── param_node.py
│   ├── sim_sensor.py
│   ├── decision_node.py
│   ├── mock_driver.py
│   └── lifecycle_demo.py
├── launch/
│   └── demo_system.launch.py
└── config/
    └── params.yaml
```

## 四、实操步骤（手把手）

> 仓库对照：`code/src/my_bringup/`。学员侧 `~/ros2_ws`。

### 步骤 0 · 打开终端

```bash
cd ~/ros2_ws/src/my_bringup
```

**预期**：能看到 `package.xml  setup.py  my_bringup/  launch/  config/`。

### 步骤 1 · 核对 package.xml 依赖

打开 `package.xml`，确认（完整版见仓库）：

```xml
<!-- ~/ros2_ws/src/my_bringup/package.xml -->
<?xml version="1.0"?>
<?xml-model href="http://download.ros.org/schema/package_format3.xsd" schematypens="http://www.w3.org/2001/XMLSchema"?>
<package format="3">
  <name>my_bringup</name>
  <version>0.1.0</version>
  <description>S1 模块4：参数、Launch、多节点小系统</description>
  <maintainer email="lddzwxy@gmail.com">laoding</maintainer>
  <license>Apache-2.0</license>

  <depend>rclpy</depend>
  <depend>std_msgs</depend>
  <depend>geometry_msgs</depend>
  <depend>launch</depend>
  <depend>launch_ros</depend>

  <export>
    <build_type>ament_python</build_type>
  </export>
</package>
```

**为什么这几条**：`rclpy` 节点运行时；`std_msgs` String；`geometry_msgs` Twist；`launch` / `launch_ros` launch 文件用。

**预期**：`import` 过的包都能在 `<depend>` 里找到对应项。

### 步骤 2 · 自查 entry_points 与文件一致

```bash
ls my_bringup/*.py
grep -A20 entry_points setup.py
```

**预期**：每个 `.py`（除 `__init__.py`）都在 `console_scripts` 有条目，且 `包名.模块名:main` 三段正确。

### 步骤 3 · 用 rosdep 补齐依赖

```bash
cd ~/ros2_ws
rosdep install --from-paths src -y --ignore-src
```

**预期**：全部 `installed` 或 `#All required rosdeps installed successfully`。

若报：

```text
ERROR: the following packages/stacks could not have their rosdep keys resolved
```

→ 通常是 `package.xml` 里写了不存在的依赖名，或没 `rosdep update`（先执行一次 `sudo rosdep init && rosdep update`，模块 0 应已做过）。

## 五、关键 API / 命令详解

| 名称 | 作用 |
| ---- | ---- |
| `<depend>xxx</depend>` | 声明运行/构建依赖，rosdep 依据 |
| `<build_type>ament_python</build_type>` | 声明包类型 |
| `rosdep install --from-paths src -y --ignore-src` | 按 package.xml 装依赖 |
| `rosdep update` | 更新 rosdep 数据库 |
| `colcon test` | 跑包内测试/lint |
| `ament_flake8` | PEP8 风格检查（测试依赖） |
| `ament_pep257` | docstring 检查（测试依赖） |
| README 版本卡 | OS / ROS / Python / 启动命令 |

## 六、常见坑

| 报错 / 现象 | 原因 | 解法 |
| ----------- | ---- | ---- |
| 换机后 `ModuleNotFoundError` / 缺消息包 | 依赖只装在旧机器，package.xml 没写 | 补 `<depend>`，跑 rosdep |
| `rosdep` 报 `Unable to locate rosdep definition` | 依赖名拼错 / 未 init | 核对名字；`sudo rosdep init && rosdep update` |
| `rosdep` 报 `Unsupported OS` | 非 Ubuntu 或源问题 | 课程环境用 Ubuntu 24.04 |
| 别人问"你什么版本能跑"答不上 | README 没版本卡 | 写明 Jazzy + Python 3.12 |
| README 命令复制失败 | 路径写死 `/home/老名字` | 统一写 `~/ros2_ws` |
| lint 一堆 E501 行太长 | 未换行 | 控制在 79–100 字符内 |
