## 三、理论讲解

### 3.1 为什么分三层？

真实机器人软件几乎都是"感知 → 决策 → 执行"：

| 层 | 干什么 | 本课节点 | 比喻 |
| -- | ------ | -------- | ---- |
| 感知 | 看世界 | `sim_sensor` | 眼睛 |
| 决策 | 想怎么办 | `decision_node` | 大脑 |
| 执行 | 动起来 | `mock_driver` | 手脚 |

好处：每层可单独替换。真雷达来了换 `sim_sensor`，真底盘来了换 `mock_driver`，决策代码不动。

### 3.2 话题契约：先约定再写码

| 话题 | 类型 | 谁发 | 谁收 |
| ---- | ---- | ---- | ---- |
| `/detection` | `std_msgs/msg/String` | sim_sensor | decision_node |
| `/cmd_vel` | `geometry_msgs/msg/Twist` | decision_node | mock_driver |

**类型必须严格一致**。`String` 对 `String`，`Twist` 对 `Twist`，差一个字母都连不上（DDS 层直接拒绝配对）。

`/cmd_vel` 遵守系列 CONTRACT：`linear.x` 线速度 m/s，`angular.z` 角速度 rad/s。

### 3.3 命名空间：给整栈加"姓"

多台机器人同机调试时，全局话题会互相踩。用 `namespace='robot1'`：

```text
/robot1/sim_sensor
/robot1/detection      ← 绝对话题以 / 开头时不进命名空间！
/robot1/cmd_vel
```

注意：代码里话题写成 `'/detection'`（**以 `/` 开头的绝对话题**）会**跳过**命名空间；写 `'detection'`（相对话题）才会进命名空间。这是新手最迷惑的一点。

### 3.4 数据流怎么走

```text
timer(5Hz)            callback                 callback
sim_sensor  --String-->  decision_node  --Twist-->  mock_driver
发布距离=1.23           距离<0.5? 停:走            打印"执行"
```

决策节点是典型的"订阅再发布"中间层：进来是感知数据，出去是控制指令。

### 步骤 1 · 写 sim_sensor.py（感知层）

**动机**：没有真雷达时，用随机数模拟"障碍距离"，让链路先转起来。

```python
#!/usr/bin/env python3
# 模拟感知节点：定时发布模拟检测结果（感知层）
# 教学点：多节点系统中的上游发布者

import random

import rclpy
from rclpy.node import Node
from std_msgs.msg import String


class SimSensor(Node):
    """模拟雷达/视觉检测：随机发布障碍距离。"""

    def __init__(self):
        super().__init__('sim_sensor')
        self.declare_parameter('publish_frequency', 5.0)
        self.declare_parameter('min_distance', 0.2)

        frequency = self.get_parameter('publish_frequency').value
        # 距离下限：随机数的最小值（上限固定 3.0 m）
        self.min_distance = self.get_parameter('min_distance').value
        self.publisher_ = self.create_publisher(String, '/detection', 10)
        self.timer = self.create_timer(1.0 / max(frequency, 0.1), self.timer_callback)
        self.get_logger().info('sim_sensor 开始发布 /detection')

    def timer_callback(self):
        # 模拟障碍距离：min_distance ~ 3.0 m，下限由参数决定
        distance = round(random.uniform(self.min_distance, 3.0), 2)
        msg = String()
        msg.data = f'distance={distance}'
        self.publisher_.publish(msg)


def main(args=None):
    rclpy.init(args=args)
    node = SimSensor()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

**预期**：文件保存；消息格式固定 `distance=<浮点>`，下游才好解析。

### 步骤 2 · 写 decision_node.py（决策层）

**动机**：把"看见障碍 → 决定停/走"的规则独立成节点；解析失败要 `warning`，别让整条链静默挂掉。

```python
#!/usr/bin/env python3
# 决策节点：订阅检测，根据距离决定前进/停止（决策层）
# 教学点：订阅-发布链路中的中间节点

import rclpy
from rclpy.node import Node
from std_msgs.msg import String
from geometry_msgs.msg import Twist


class DecisionNode(Node):
    """距离小于阈值则停车，否则前进。"""

    def __init__(self):
        super().__init__('decision_node')
        self.declare_parameter('stop_distance', 0.5)

        self.stop_distance = self.get_parameter('stop_distance').value
        self.cmd_pub = self.create_publisher(Twist, '/cmd_vel', 10)
        self.sub = self.create_subscription(
            String, '/detection', self.detection_callback, 10)

        self.get_logger().info(
            f'decision_node 就绪，停车阈值 {self.stop_distance} m')

    def detection_callback(self, msg: String):
        # 消息形如 "distance=1.23"
        try:
            distance = float(msg.data.split('=')[1])
        except (IndexError, ValueError):
            self.get_logger().warning(f'无法解析检测消息: {msg.data!r}')
            return

        cmd = Twist()
        if distance < self.stop_distance:
            # 障碍过近：停车
            cmd.linear.x = 0.0
            self.get_logger().warning(f'障碍过近 ({distance:.2f} m)，停车')
        else:
            cmd.linear.x = 0.2
        self.cmd_pub.publish(cmd)


def main(args=None):
    rclpy.init(args=args)
    node = DecisionNode()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

**预期**：订阅类型 `String` 与 sim_sensor 发布类型一致；输出类型 `Twist`。

### 步骤 3 · 写 mock_driver.py（执行层）

**动机**：真底盘还没上车，先"假装执行"；回调里只打日志，**绝不能 sleep/阻塞**。

```python
#!/usr/bin/env python3
# 模拟驱动节点：订阅 /cmd_vel 并打印执行动作（执行层）
# 教学点：订阅者作执行器；回调不要阻塞

import rclpy
from rclpy.node import Node
from geometry_msgs.msg import Twist


class MockDriver(Node):
    """打印收到的速度指令，模拟底层驱动。"""

    def __init__(self):
        super().__init__('mock_driver')
        self.sub = self.create_subscription(
            Twist, '/cmd_vel', self.cmd_callback, 10)
        self.count = 0
        self.get_logger().info('mock_driver 等待 /cmd_vel …')

    def cmd_callback(self, msg: Twist):
        self.count += 1
        if self.count % 10 == 1:
            self.get_logger().info(
                f'执行: linear.x={msg.linear.x:.2f}, angular.z={msg.angular.z:.2f}')


def main(args=None):
    rclpy.init(args=args)
    node = MockDriver()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()


if __name__ == '__main__':
    main()
```

**预期**：每 10 条打 1 条日志，避免刷屏。

## 五、关键 API / 命令详解

| 名称 | 作用 |
| ---- | ---- |
| `create_publisher(Type, topic, depth)` | 建发布者 |
| `create_subscription(Type, topic, cb, depth)` | 建订阅者 |
| `create_timer(period, cb)` | 周期驱动发布 |
| `msg.data = 'distance=1.23'` | String 约定格式（契约） |
| `Twist().linear.x` | 线速度指令 |
| `ros2 topic echo <topic>` | 实时打印消息 |
| `ros2 topic hz <topic>` | 测实际频率 |
| `ros2 topic info <topic>` | 看类型与 pub/sub 数量 |
| `ros2 interface show <type>` | 查看消息字段 |
| `namespace='robot1'` | 整栈加命名空间（相对话题才生效） |

## 六、常见坑

| 报错 / 现象 | 原因 | 解法 |
| ----------- | ---- | ---- |
| `ros2 topic echo` 无数据 | 发布节点没起 / 话题名不一致 | `ros2 node list` + `ros2 topic list` 对照 |
| `Message types do not match` | 两端类型不一致 | `ros2 topic info -v` 看 Type |
| 消息收到了但决策不动作 | 解析格式变了 | 保持 `distance=<float>`，看 warn 日志 |
| 命名空间加了但话题还是全局 | 话题写成 `'/xxx'` 绝对名 | 去掉开头 `/` 用相对名 |
| mock_driver 刷屏拖慢系统 | 每条消息都打日志 | 节流（`count % 10`） |
| 回调里 sleep 导致丢消息 | 阻塞了 executor | 回调只做短计算，长任务另开线程/行为 |
