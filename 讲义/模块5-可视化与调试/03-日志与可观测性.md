## 三、理论讲解

### 3.1 print 的三大问题

| 问题 | 后果 |
| ---- | ---- |
| 没有级别 | 正常心跳和致命错误长得一样 |
| 不进统一日志系统 | rqt_console / 日志文件里看不见 |
| 无节点名/时间戳 | 多节点时不知道谁喊的 |

ROS2 的 `self.get_logger()` 把这三样都补上了。

### 3.2 五个级别怎么选

| 级别 | 什么时候用 | 例子 |
| ---- | ---------- | ---- |
| `debug` | 开发细节，默认常被过滤 | 进入回调、中间变量 |
| `info` | 正常里程碑，值得知道 | 启动成功、每 20 条摘要一次 |
| `warning` | 不正常但还能跑 | 速度偏大、解析失败、降级 |
| `error` | 功能失败，需要人看 | 连不上硬件、写文件失败 |
| `fatal` | 整个进程要挂 | 不可恢复，准备退出 |

口诀：**info 讲进度，warn 讲异常值，error 讲失败原因**。

### 3.3 一条好日志 = 上下文三件套

```text
变量（谁/什么） + 期望（应该怎样） + 实际（现在怎样）
```

坏例子：`print(distance)` 
好例子：`warning(f'障碍过近 ({distance:.2f} m)，停车阈值 {self.stop_distance} m')`

出了问题，日志自己会说话。

### 3.4 不要刷屏

10 Hz 控制循环每条都 info = 一分钟 600 行，真正的错误被淹没。 
套路：

- 状态变化时才打（频率变更那条）；
- 每 N 条打一条摘要（`count % 20 == 1`）；
- 持续异常打 warn，但可配节流。

### 3.5 了解即可：流缓冲

环境变量 `RCUTILS_LOGGING_BUFFERED_STREAM=1` 可让日志进缓冲再刷出，减少某些终端的锁竞争。入门阶段知道有这个开关即可，不强求。

### 步骤 1 · 对照：print 版 vs logger 版

打开 `velocity_subscriber.py`，重点看回调里的写法：

```python
# ~/ros2_ws/src/my_topic_demo/my_topic_demo/velocity_subscriber.py 片段
def listener_callback(self, msg: Twist):
    """收到一条速度指令就处理一次；回调要短小、不要阻塞。"""
    self.count += 1
    lin = msg.linear.x
    ang = msg.angular.z

    # 简单合法性检查：异常值用 warning
    if abs(lin) > 2.0 or abs(ang) > 2.0:
        self.get_logger().warning(
            f'速度偏大: linear.x={lin:.2f}, angular.z={ang:.2f}')

    # 每 20 条打印一次，避免刷屏
    if self.count % 20 == 1:
        self.get_logger().info(
            f'[{self.count}] 收到: linear.x={lin:.2f}, angular.z={ang:.2f}')
```

**为什么这么写**：

- 合法性检查 → `warn`：值到了但不合理；
- 摘要 → `info` + 节流：证明链路活着；
- 启动一行 `info`：知道订阅的是哪个话题。

**预期**：全文没有 `print(`；用的是 `self.get_logger().info/warn`。

## 五、关键 API / 命令详解

| 名称 | 作用 |
| ---- | ---- |
| `self.get_logger()` | 获取本节点 logger |
| `.debug/.info/.warning/.error/.fatal` | 分级输出 |
| f-string 拼上下文 | 变量 + 期望 + 实际 |
| 节流（`count % N`） | 防刷屏 |
| `rqt_console` 过滤器 | 按级别/节点/文本筛日志 |
| `ros2 topic pub --once ...` | 手动发一条，专门测异常分支 |
| `RCUTILS_LOGGING_BUFFERED_STREAM` | 日志缓冲（了解） |

日志级别速查：

```text
debug < info < warning < error < fatal
```

## 六、常见坑

| 报错 / 现象 | 原因 | 解法 |
| ----------- | ---- | ---- |
| 只 `print` 数字，无上下文 | 没写期望/实际 | f-string 带上阈值和单位 |
| 中文日志乱码 | 终端编码 | Windows Terminal + UTF-8；`export LANG=zh_CN.UTF-8` |
| Error 满天飞，真错误被淹没 | 级别滥用 | 能跑的异常用 warning，失败才 error |
| rqt_console 空白 | 级别被过滤 / 节点没起 | 重置过滤；`ros2 node list` |
| 每条消息都 info，卡顿 | 刷屏 + IO | 节流：摘要 / 状态变化才打 |
| logger 里调用了耗时操作 | 回调被拖慢 | 日志只格式化短字符串 |
| 多节点分不清谁打的 | 没注意 Node 列 | 日志本身带节点名，console 按 Node 排序 |
