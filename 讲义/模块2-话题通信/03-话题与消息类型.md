## 三、理论讲解

### 3.1 话题 = 名字 + 类型

一个 Topic 必须有：

1. **话题名**：如 `/cmd_vel`（全局名以 `/` 开头）；
2. **消息类型**：如 `geometry_msgs/msg/Twist`。

类型不匹配 = 谁也听不懂谁。发布和订阅必须用**同一个类型**。

### 3.2 Twist：本系列的速度契约

```text
geometry_msgs/msg/Twist
├── Vector3 linear     # 线速度，单位 m/s
│   ├── x   ← 前进/后退（本系列只用这个）
│   ├── y
│   └── z
└── Vector3 angular    # 角速度，单位 rad/s
    ├── x
    ├── y
    └── z   ← 左转/右转（本系列只用这个）
```

约定（来自 `code/CONTRACT.md`，**全系列不改名**）：

| 话题 | 类型 | 含义 |
| ---- | ---- | ---- |
| `/cmd_vel` | `geometry_msgs/msg/Twist` | `linear.x` 前进 m/s，`angular.z` 转向 rad/s |

### 3.3 常用消息包

| 包 | 典型类型 | 用在哪 |
| -- | -------- | ------ |
| `std_msgs` | `String` / `Float32` / `Bool` | 简单数据、状态字 |
| `geometry_msgs` | `Twist` / `PoseStamped` | 速度、位姿 |
| `sensor_msgs` | `LaserScan` / `Imu` / `BatteryState` | 传感器 |
| `nav_msgs` | `Odometry` | 里程计 |

### 3.4 `topic pub` 的 YAML 写法

```bash
ros2 topic pub --once /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 1.0}}"
```

`{linear: {x: 1.0}}` 是**嵌套字典**，缩进错了就解析失败。可以只写你要填的字段，其余取默认 0。

## 四、实操步骤（手把手）

### 步骤 0 · 打开终端

Windows Terminal → Ubuntu。

**预期**：`<用户名>@<电脑名>:~$` 提示符。

### 步骤 1 · 启动 turtlesim

```bash
source /opt/ros/jazzy/setup.bash
ros2 run turtlesim turtlesim_node
```

**预期**：弹出蓝色小窗，中间有一只乌龟。

### 步骤 2 · 列出话题

另开终端（记得 source）：

```bash
ros2 topic list -t
```

**预期**：至少看到（类型可能写成 `[geometry_msgs/msg/Twist]`）：

```text
/parameter_events [rcl_interfaces/msg/ParameterEvent]
/rosout [rcl_interfaces/msg/Log]
/turtle1/cmd_vel [geometry_msgs/msg/Twist]
/turtle1/color_sensor [turtlesim/msg/Color]
/turtle1/pose [turtlesim/msg/Pose]
```

### 步骤 3 · 查看话题详情

```bash
ros2 topic info /turtle1/cmd_vel
```

**预期**：

```text
Type: geometry_msgs/msg/Twist
Publisher count: 0
Subscription count: 1
```

（此时 teleop 还没开，Publisher 可能是 0 或 1。）

### 步骤 4 · 看消息类型定义

```bash
ros2 interface show geometry_msgs/msg/Twist
```

**预期**：

```text
# This expresses velocity in free space broken into its linear and angular parts.

Vector3  linear
Vector3  angular
```

再看子类型：

```bash
ros2 interface show geometry_msgs/msg/Vector3
```

**预期**：看到 `float64 x / y / z`。

### 步骤 5 · 实时监听话题

```bash
ros2 topic echo /turtle1/cmd_vel
```

**预期**：暂时没数据（没人发布），光标停住等待。

### 步骤 6 · 发布一条指令让乌龟动

第三个终端：

```bash
ros2 topic pub --once /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 1.0}}"
```

**预期**：

- 终端打印 `publishing #1` 之类；
- 乌龟向前走一小段；
- 步骤 5 的 echo 出现一条 `linear: x: 1.0`。

### 步骤 7 · 测频率

先开键盘遥控：

```bash
ros2 run turtlesim turtle_teleop_key
```

按住方向键，再：

```bash
ros2 topic hz /turtle1/cmd_vel
```

**预期**：类似

```text
average rate: 8.123
	min: 0.087s max: 0.143s std dev: 0.012s window: 34
```

松开按键后 hz 会停（没人发了）。

### 步骤 8 · 契约话题预览

```bash
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.2}, angular: {z: 0.1}}"
```

**预期**：命令成功发出（此时还没订阅者，数据是"无人收听的广播"，下一集我们自己写订阅者）。

## 五、关键 API / 命令详解

| 名称 | 作用 |
| ---- | ---- |
| `ros2 topic list -t` | 列出话题及类型 |
| `ros2 topic info <话题>` | 查看类型与 pub/sub 数量 |
| `ros2 topic echo <话题>` | 实时打印收到的消息 |
| `ros2 topic hz <话题>` | 统计发布频率 |
| `ros2 topic pub [--once] <话题> <类型> <YAML>` | 手动发布消息 |
| `ros2 interface show <包/msg/类型>` | 显示消息字段定义 |
| `ros2 interface list` | 列出所有可用接口 |

YAML 填字段的小技巧：

```bash
# 只填 linear.x，其余默认 0
"{linear: {x: 0.5}}"

# 填两个字段
"{linear: {x: 0.5}, angular: {z: 0.3}}"
```

## 六、常见坑

| 报错 / 现象 | 原因 | 解法 |
| ----------- | ---- | ---- |
| `Type mismatch` 或 echo 无数据 | pub 与 sub 类型不一致 | `ros2 topic info` 对齐类型 |
| `pub` 报 YAML 解析错误 | 大括号/缩进写错 | 用 `"{linear: {x: 1.0}}"` 引号包住 |
| echo 一直空白 | 话题名写错，或没人发布 | `ros2 topic list` 核对；先 `pub` 一条试试 |
| `hz` 显示 `no new messages` | 1 秒内没有新消息 | 确认 publisher 在跑；teleop 要按住键 |
| turtlesim 窗口出不来 | 没装或没图形环境 | `sudo apt install ros-jazzy-turtlesim`；WSL 需有 WSLg |
| 以为 `pub` 一次会持续发 | `--once` 只发一条 | 去掉 `--once` 会按 1 Hz 重复发 |
