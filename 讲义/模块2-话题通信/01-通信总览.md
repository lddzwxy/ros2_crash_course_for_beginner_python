## 一、本集目标

建立 ROS2 三种通信方式的**直觉**：

- Topic = 广播（连续说，谁爱听谁听）
- Service = 打电话（一问一答，等对方回话）
- Action = 点外卖（下单、盯进度、还能取消）

学完你能对"速度指令、查电量、导航到点"这类场景，**立刻判断该用哪种**。

## 三、理论讲解

### 3.1 生活化比喻

```text
Topic   = 校园广播站
         广播站不停地播，谁想听谁打开收音机。
         广播站不知道谁在听，也不等谁回应。

Service = 打电话
         你拨过去，问一句"食堂几点关？"，
         对方回答"九点"，这通电话结束。
         一对一，有明确的"问"和"答"。

Action  = 点外卖
         你下单（goal），App 显示"骑手已接单 / 已到店 / 
         正在配送 / 已送达"（feedback），
         路上你还能点"取消订单"（cancel），
         最后拿到结果（result）。
```

### 3.2 三种通信的本质区别

| 维度 | Topic | Service | Action |
| ---- | ----- | ------- | ------ |
| 比喻 | 广播 | 打电话 | 点外卖 |
| 方向 | 单向连续 | 一问一答 | 下单→进度→结果 |
| 频率 | 高（10~1000 Hz） | 低（偶发） | 低（一个任务一次） |
| 有无反馈 | 无 | 无（只有最终 response） | 有 feedback |
| 能否取消 | 不适用 | 不能 | 能 |
| 典型例子 | 传感器、速度指令 | 查电量、开关灯 | 导航、抓取、前进 N 米 |
| 数据流向 | 1 对多（发布者不关心谁收） | 1 对 1（请求→响应） | 1 对 1（带生命周期） |

### 3.3 什么时候绝对别用 Service？

Service 是**阻塞式**的：客户端发请求后要等响应。

如果用 Service 传**高频传感器数据**（比如 10 Hz 的激光），每条消息都要经历"请求→等→响应"，系统很快被拖垮。

记住：**数据流用 Topic，请求响应用 Service**。

### 3.4 Action 不是"更快的 Service"

有人以为 Action = 加强版 Service，这是错的。

Action 多出来的能力是：

1. **反馈**（feedback）：执行过程中持续报告进度；
2. **取消**（cancel）：中途喊停；
3. **长时执行**：跑几分钟也不会把通信层卡住。

如果一个任务**瞬间完成、不要进度、不能取消**（比如开灯），用 Service 就够了，别上 Action。

## 五、关键 API / 命令详解

本集是概念集，没有代码 API。记住这张"选型口诀"：

| 你要的是…… | 选 |
| ---------- | -- |
| 持续的数据流（传感器、状态、指令） | Topic |
| 一次请求要一个明确结果 | Service |
| 耗时任务 + 进度 + 可取消 | Action |
| 配置项（可读可写、带范围校验） | Parameter（模块 4 讲） |

对应 ROS2 术语：

| 通信 | 描述文件 | 核心对象 |
| ---- | -------- | -------- |
| Topic | `.msg` | `Publisher` / `Subscription` |
| Service | `.srv`（request `---` response） | `Service` / `Client` |
| Action | `.action`（goal `---` result `---` feedback） | `ActionServer` / `ActionClient` |

## 六、常见坑

| 报错 / 现象 | 原因 | 解法 |
| ----------- | ---- | ---- |
| 用 Service 传 10 Hz 激光数据，系统卡死 | Service 是阻塞一问一答，不适合数据流 | 换 Topic |
| 把 Action 当"更快的 Service" | 没分清"反馈/取消"才是 Action 的核心 | 短任务用 Service，长任务用 Action |
| 看到"有数据要传"就全用 Topic | 请求-响应场景没有"答"，调用方不知道成没成 | 要确认结果的用 Service |
| 服务回调里再同步 call 另一个 Service | 回调阻塞，可能死锁 | 见模块 3 坑表 |
